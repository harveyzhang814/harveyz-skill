# Hook 代码模板

Step 6 生成 hooks 时参考此文件。

---

## 通用结构

每个 hook 文件由三部分组成：

```
固定头部（非 MANAGED，每次重新生成时原样保留）
│
├── # --- BEGIN MANAGED: <block-id> (hash:<8hex>) ---
│   <配置驱动的生成内容>
│   # --- END MANAGED: <block-id> ---
│
│   （可有多个 MANAGED 块）
│
用户自定义区（MANAGED 块之外，永不覆盖）
│
固定尾部：exit 0
```

### MANAGED 块 ID 规范

| hook 文件 | 块 ID |
|-----------|-------|
| pre-commit | `branches.protected/<branch-name>` |
| commit-msg | `commit-msg/merge-via`、`commit-msg/format`、`commit-msg/length` |
| pre-push | `pre-push/merge-via`、`pre-push/tags`、`pre-push/force-push` |
| post-checkout | `post-checkout/branch-naming` |

---

## pre-commit

触发条件：`branches.protected` 存在时生成。

**固定头部：**
```sh
#!/bin/sh
# Generated by init-workflow v5.0.3
# Manual edits outside MANAGED blocks are preserved across runs.
BRANCH=$(git symbolic-ref --short HEAD 2>/dev/null)
[ -z "$BRANCH" ] && exit 0
IS_MERGE=0
[ -f "$(git rev-parse --git-dir)/MERGE_HEAD" ] && IS_MERGE=1

merge_source_branch() {
    msg_file="$(git rev-parse --git-dir)/MERGE_MSG"
    [ -f "$msg_file" ] || { printf ''; return; }
    head -1 "$msg_file" | sed "s/Merge branch '//;s/'.*//"
}
```

**每个保护分支生成一个 MANAGED 块**（以 main 为例，merge_from: staging, release/*）：
```sh
# --- BEGIN MANAGED: branches.protected/main (hash:<hash>) ---
if [ "$BRANCH" = "main" ]; then
    if [ "$IS_MERGE" -eq 0 ]; then
        echo "❌ 禁止直接在 main 上提交。main 只接受来自 staging 或 release/* 的合并。"
        exit 1
    fi
    SRC=$(merge_source_branch)
    case "$SRC" in
        staging|release/*) exit 0 ;;
        *) echo "❌ main 只接受来自 staging 或 release/* 的合并，当前来源：'${SRC:-unknown}'"; exit 1 ;;
    esac
fi
# --- END MANAGED: branches.protected/main ---
```

`case` 模式从配置的 `merge_from` 列表动态生成，`|` 分隔。
`allow_direct_commit: true` 时，非合并分支里的 `echo "❌ …"` 改为 `echo "⚠️ …"` 警告，`exit 1` 改为 `exit 0`（直接提交放行；只把 `exit 1` 换成 `echo` 会落到下面的来源检查，照样被拒）。

**合并目标分支的块（`branches.protected/<merge_target>`）：** 合并目标 = `resolved.env` 的 `merge_target`。该分支用下面的变体，其他受保护分支（如上面的 `main`）仍用上面的写法，不变。变体保留“禁止直接提交”，删去 `MERGE_MSG` 来源判断（合并来源与标记由 `commit-msg/merge-via` 负责），报错改为指向合并脚本。占位：`<merge_target>`（合并目标分支名）、`<merge_script>`（`scripts/merge-to-<merge_target>.sh`）。
没有合并目标（没有受保护分支的 `merge_from` 列有 `"feature/*"`）时，不生成该变体，所有受保护分支都用上面的写法。
```sh
# --- BEGIN MANAGED: branches.protected/<merge_target> (hash:<hash>) ---
if [ "$BRANCH" = "<merge_target>" ]; then
    if [ "$IS_MERGE" -eq 0 ]; then
        echo "❌ 禁止直接在 <merge_target> 上提交。请在 feature/*、fix/*、chore/* 或 doc/* 分支开发，合并请用 <merge_script>。"
        exit 1
    fi
fi
# --- END MANAGED: branches.protected/<merge_target> ---
```
合并进行中（`MERGE_HEAD` 存在，如手工解决冲突后的 `git commit`）pre-commit 不判来源，直接放行，由随后的 `commit-msg/merge-via` 判定标记。

**固定尾部：**`exit 0`

## commit-msg

触发条件：`commit_message.enforce: true` 时生成。

**固定头部：**
```sh
#!/bin/sh
# Generated by init-workflow v5.0.3
MSG=$(cat "$1")
SUBJECT=$(printf '%s\n' "$MSG" | head -1)
SUBJECT=$(printf '%s\n' "$SUBJECT" | sed '/^#/d' | sed 's/^[[:space:]]*//')
[ -z "$SUBJECT" ] && exit 0
```

**合并标记 MANAGED 块（`commit-msg/merge-via`）：**
生成条件：存在合并目标（`resolved.env` 的 `merge_target` 非空，即某个受保护分支的 `merge_from` 列有 `"feature/*"`）。没有合并目标时不生成；此时 `commit-msg` 仅因 `commit_message.enforce: true` 才生成。
位置：必须放在 `commit-msg/format` 之前。`commit-msg/format` 首行遇 `MERGE_HEAD` 即 `exit 0`，排在它后面这个块永远执行不到。
占位：`<merge_target>`（合并目标分支名）、`<merge_trailer>`（`Merge-Via: merge-to-<merge_target>.sh`）、`<merge_script>`（`scripts/merge-to-<merge_target>.sh`）。
判定：存在 `MERGE_HEAD`、当前分支是合并目标、提交信息中没有整行等于 `<merge_trailer>` 的行、且主题不是远端同步合并（以 `Merge branch '<merge_target>' of ` 开头）时拒绝。
```sh
# --- BEGIN MANAGED: commit-msg/merge-via (hash:<hash>) ---
if [ -f "$(git rev-parse --git-dir)/MERGE_HEAD" ] \
    && [ "$(git symbolic-ref --short HEAD 2>/dev/null)" = "<merge_target>" ]; then
    if ! grep -qxF -- "<merge_trailer>" "$1"; then
        case "$SUBJECT" in
            "Merge branch '<merge_target>' of "*) ;;
            *)
                echo "❌ 禁止手动合并进 <merge_target>。请改用 <merge_script>。"
                exit 1
                ;;
        esac
    fi
fi
# --- END MANAGED: commit-msg/merge-via ---
```

**格式检查 MANAGED 块（`commit-msg/format`）：**
块内首行固定豁免合并提交（`MERGE_HEAD` 存在即视为合并提交，直接放行，不做格式/长度校验）：
```sh
# --- BEGIN MANAGED: commit-msg/format (hash:<hash>) ---
[ -f "$(git rev-parse --git-dir)/MERGE_HEAD" ] && exit 0
if ! printf '%s\n' "$SUBJECT" | grep -qE "<pattern>"; then
    echo "❌ 提交信息不符合 Conventional Commits 规范"
    ...
    exit 1
fi
# --- END MANAGED: commit-msg/format ---
```
- `format: conventional`：将 `types` 列表拼接为正则 `^(feat|fix|...)(\(.+\))?: .+`；`require_scope: false` 时 scope 部分为可选 `(\(.+\))?`
- `format: regex`：使用配置的 `pattern` 字段直接作为 grep 表达式

若不豁免合并提交，git 默认生成的 "Merge branch '...'" 信息永远无法通过 Conventional Commits 校验；而若强行要求合并提交也写成 conventional 格式，pre-commit 中 `merge_source_branch()` 依赖 git 默认 `MERGE_MSG` 文本解析来源分支，自定义信息会导致解析失败。豁免合并提交让两个 hook 同时成立。

**长度检查 MANAGED 块（`commit-msg/length`）：**
```sh
# --- BEGIN MANAGED: commit-msg/length (hash:<hash>) ---
LEN=$(printf '%s' "$SUBJECT" | wc -c | tr -d ' ')
if [ "$LEN" -gt <max_subject_length> ]; then
    echo "❌ 提交信息首行超过 <max_subject_length> 个字符（当前 ${LEN} 个字符）"
    exit 1
fi
# --- END MANAGED: commit-msg/length ---
```

**固定尾部：**`exit 0`

## pre-push

触发条件：`tags.enforce: true`、`push_rules.enforce: true` 或存在合并目标（需生成 `pre-push/merge-via`）时生成。

**固定头部：**
```sh
#!/bin/sh
# Generated by init-workflow v5.0.3
while IFS=' ' read -r local_ref local_sha remote_ref remote_sha; do
    case "$remote_ref" in
```

**合并标记 MANAGED 块（`pre-push/merge-via`）：**
生成条件：存在合并目标；没有合并目标时不生成。
位置：放在 `while` 行与 `case "$remote_ref" in` 行之间，是循环体里独立的 `if`，**不是** `case` 分支。原因：`pre-push/force-push` 的分支 `refs/heads/main|refs/heads/staging)` 也匹配合并目标，`case` 取第一个命中的分支，若 merge-via 也写成分支，两者必有一个被遮蔽；独立 `if` 使两个检查互不影响。仅此块存在时 `case` 内可没有分支（`case ... in esac` 合法）。
占位：`<merge_target>`、`<merge_trailer>`（同 `commit-msg/merge-via`）、`<merge_script>`。
判定：推送目标是 `refs/heads/<merge_target>` 且非删除时，检查 `remote_sha..local_sha` 范围内的 first-parent 提交（`remote_sha` 全零则只查 `local_sha`）；每个提交须有整行等于 `<merge_trailer>` 的行，或主题以 `Merge branch '<merge_target>' of ` 开头，否则拒绝。第二父侧（功能分支上的提交）不检查。
```sh
# --- BEGIN MANAGED: pre-push/merge-via (hash:<hash>) ---
    if [ "$remote_ref" = "refs/heads/<merge_target>" ] \
        && [ "$local_sha" != "0000000000000000000000000000000000000000" ]; then
        if [ "$remote_sha" = "0000000000000000000000000000000000000000" ]; then
            CHECK_SHAS="$local_sha"
        else
            CHECK_SHAS=$(git rev-list --first-parent "$remote_sha..$local_sha" 2>/dev/null)
        fi
        for SHA in $CHECK_SHAS; do
            if git log -1 --format=%B "$SHA" | grep -qxF -- "<merge_trailer>"; then
                continue
            fi
            case "$(git log -1 --format=%s "$SHA")" in
                "Merge branch '<merge_target>' of "*) continue ;;
            esac
            echo "❌ 推送被拒：$SHA 不是经 <merge_script> 产生的合并（缺少 '<merge_trailer>' 行）。"
            exit 1
        done
    fi
# --- END MANAGED: pre-push/merge-via ---
```

**tag 检查 MANAGED 块（`pre-push/tags`，仅当 `tags.enforce: true`）：**
此块的 `'<pattern 1>' '<pattern 2>' ...` 是 tag 命名模式，取配置 `tags.allowed_patterns`（`resolved.env` 不含），每条加单引号。
```sh
# --- BEGIN MANAGED: pre-push/tags (hash:<hash>) ---
        refs/tags/*)
            TAG=$(printf '%s' "$remote_ref" | sed 's|refs/tags/||')
            MATCHED=0
            for PATTERN in '<pattern 1>' '<pattern 2>' ...; do
                printf '%s\n' "$TAG" | grep -qE "$PATTERN" && MATCHED=1 && break
            done
            if [ "$MATCHED" -eq 0 ]; then
                echo "❌ Tag 命名不符合规范：$TAG"
                exit 1
            fi
            ;;
# --- END MANAGED: pre-push/tags ---
```

**force push 检查 MANAGED 块（`pre-push/force-push`，仅当 `push_rules.enforce: true`）：**
```sh
# --- BEGIN MANAGED: pre-push/force-push (hash:<hash>) ---
        refs/heads/main|refs/heads/staging)
            if [ "$local_sha" = "0000000000000000000000000000000000000000" ]; then
                echo "❌ 禁止删除受保护分支：$remote_ref"
                exit 1
            fi
            if [ "$remote_sha" != "0000000000000000000000000000000000000000" ]; then
                if ! git merge-base --is-ancestor "$remote_sha" "$local_sha" 2>/dev/null; then
                    echo "❌ 禁止强制推送到受保护分支：$remote_ref"
                    exit 1
                fi
            fi
            ;;
# --- END MANAGED: pre-push/force-push ---
```

`refs/heads/main|refs/heads/staging` 从 `push_rules.block_force_push` 列表动态生成。

`local_sha` 全零表示删除远端分支，与 force push 是两码事，单独拦截并报出不同的提示。真正的非 fast-forward（force push）检测用 `git merge-base --is-ancestor "$remote_sha" "$local_sha"`：若远端当前 SHA 不是本地待推送 SHA 的祖先，说明历史被重写，即 force push；`remote_sha` 全零（推送全新分支）时跳过该判断，因为此时没有旧历史可比较。

**固定尾部：**
```sh
    esac
done
exit 0
```

## post-checkout

触发条件：`branch_naming.enforce: true` 时生成。

**固定头部：**
```sh
#!/bin/sh
# Generated by init-workflow v5.0.3
[ "$3" = "1" ] || exit 0
BRANCH=$(git symbolic-ref --short HEAD 2>/dev/null)
[ -z "$BRANCH" ] && exit 0
```

**命名检查 MANAGED 块（`post-checkout/branch-naming`）：**
```sh
# --- BEGIN MANAGED: post-checkout/branch-naming (hash:<hash>) ---
case "$BRANCH" in
    <exempt-branch-1>|<exempt-branch-2>) exit 0 ;;
esac
MATCHED=0
for PATTERN in '<pattern 1>' '<pattern 2>' ...; do
    printf '%s\n' "$BRANCH" | grep -qE "$PATTERN" && MATCHED=1 && break
done
if [ "$MATCHED" -eq 0 ]; then
    echo "⚠️ 分支命名不符合规范：$BRANCH"
    echo "   允许的格式：<allowed_patterns 列表>"
fi
# --- END MANAGED: post-checkout/branch-naming ---
```

占位映射：`'<pattern 1>' '<pattern 2>' ...` = `resolved.env` 的 `naming.1..n`（按编号），**每条单独加单引号**——模式里的 `(`、`)`、`$`、`|` 不加引号会让 sh 报语法错误或被展开；exempt 列表 = `naming_exempt`（空格分隔）。

`exempt` 列表生成 case 模式（`|` 分隔）；`allowed_patterns` 逐条 grep。post-checkout 仅警告不阻断（`exit 0`，不 `exit 1`）。

**固定尾部：**`exit 0`

## MANAGED 块 hash 计算

```bash
actual_hash=$(printf '%s' "<block_content>" | git hash-object --stdin | cut -c1-8)
```

`<block_content>` = BEGIN/END 标记之间的内容，去首尾空白。

## 多行内容写入方式

禁止用 `awk -v` 传多行 shell 脚本（含换行符时 awk 报错）。正确方式：

```bash
TMPBLOCK=$(mktemp)
cat > "$TMPBLOCK" << 'BLOCKEOF'
# --- BEGIN MANAGED: branches.protected/develop (hash:PLACEHOLDER) ---
if [ "$BRANCH" = "develop" ]; then
    ...
fi
# --- END MANAGED: branches.protected/develop ---
BLOCKEOF

python3 - "$HOOKFILE" "$TMPBLOCK" << 'PYEOF'
import sys
hook = open(sys.argv[1]).read()
block = open(sys.argv[2]).read()
hook = hook.replace('\nexit 0\n', '\n' + block + '\nexit 0\n', 1)
open(sys.argv[1], 'w').write(hook)
PYEOF
rm "$TMPBLOCK"
```
