# 精简 Skill

## 简化范围与优先级

先审查 `SKILL.md` 正文，再审查正文直接或经内部文档间接引用、作为该 Skill 自身说明组成部分的只读文档。后者必须审查，优先级次于正文；范围不限目录。

按用途区分文档与可执行内容：供 Agent 阅读的说明纳入简化范围；脚本及其他可执行内容不作简化，仅在理解行为和核对文档时按需阅读。外部资料及其他 Skill 不因被引用而纳入修改范围。

## 拟定建议

1. 识别必须保留的触发条件、判断规则、步骤、输出格式、授权边界和跨 Skill 接口。
2. 删除重复、空泛和通用教程；通用能力需要提示时只留关键词。
3. 将可由既有术语或专有名词无歧义表达的说明压缩为该词；保留任务特有的条件、边界和输出要求。
4. 若能减少无关内容加载，对仅在明确情境下需要的内容采用渐进式披露；保留共同规则与始终生效的约束。
5. 将含糊表述改为明确的条件和动作；一句话能说清的规则不拆句。
6. 指令写清何时做、做什么、产出什么；解释单列，且只保留影响决策的内容。
7. 对照原文核对保留项及必要的术语、字段、路径和顺序；保留并标记无法确认的语义。

## 审批与执行

报告正文及范围内引用文档的审查结果；修改建议按文件标明位置，逐条列出修改前文本、修改后文本及理由，等待用户明确批准。获批后仅修改批准项，验证内容及引用关系一致性，在 Git 仓库中提交，报告实际改动与疑点。
