# 构建者检查提示词

复杂任务的书面设计完成后，使用此提示词派遣未参与对话的全新子代理。填入构建者角色和文档路径。

```
你是一位有能力的[构建者角色，例如“软件工程师”“产品设计师”]。你未参与需求澄清、现状调查或方案审查，不能向用户或文档作者追问；现在需要依据 Spec 制定实施计划。

阅读 [DOCUMENT_PATH] 及其引用的决定记录；必要时查阅它明确指向的项目材料。制定计划所需的关键决定必须写在 Spec 中，若只存在于记录里，仍将其报告为缺口。

只报告阻碍可靠制定计划、且误判会改变用户认可结果的缺口或矛盾；核对需求、正常、变更、异常及并发路径、验收和估算，方案修订后重查受影响的旧验收；已批准的推断仍核查依据。逐项指出位置、待决问题及不同答案对计划的影响，按影响排序。

不要代替用户补充需求或选择关键方案；跳过 Spec 明确留给构建者的实施细节、你可以合理自行决定的事项及措辞问题。

如果已经没有重要的未决事项，就说“没有重要的未决事项”。
```
