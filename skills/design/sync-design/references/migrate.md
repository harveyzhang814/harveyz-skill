# 批量迁移旧稿

把 manifest 登记的所有完成稿与设计稿迁到 SKILL.md「稿子结构」的格式，之后改稿才能局部读取。由初始化清单第 5 项或迁移模式触发。迁移是一次性成本：需要补标记的稿子要把正文读一遍。

### 1. 脚本迁移

```bash
python3 SKILL_DIR/scripts/design_html.py migrate .hskill/sync-design/manifest.json
```

脚本原地改写每份稿子，只做机械变换，不改画面：

- 删除 base64 内嵌字体（字体名保留，回退到系统字体）
- 重复图标收进图标定义区，原处改为引用；样式里有选择器指向图标内部的跳过
- 状态名恰好是某个元素的 `id` / `data-ui-state` / `data-state` 且全文唯一时，在该元素前补状态标记

输出每份稿子的前后大小、做了什么，以及 `! 待补` 的状态。少于 4 万字符的稿子不要求标记（直接全量读），不会出现在待补里。旧稿里 `───── 名称 ─────` 这类分隔注释已算作标记。

### 2. 补状态标记

待补清单以 `check` 的输出为准（第 1 步的输出可能在别的会话里，看不到）。对每份待补的稿子：

1. 先复制一份改前副本：`cp <htmlFile> <htmlFile>.pre-anchor`。
2. 读正文（样式段可跳过）。正文压成一行读不了时，先用 `outline` 和 grep 找结构，再按位置读。
3. 为每个待补状态找到画它的块，按 SKILL.md「稿子结构」的规则补标记。线索：标题、说明文字、`class`、`id`、`§` 编号，以及脚本里的场景对象或开关（靠脚本切换的稿子只有这条线索）。
   - 块已有标记但名称对不上状态名：直接改那条标记注释的文字（改名或补 `覆盖：`），不要在下面再叠一条。
   - 一块并排画了几个状态、或一个状态由几块拼出：按「稿子结构」用覆盖处理。
   - 不属于任何状态的内容（说明、对比表）被并进相邻块时，给它单独加标记。
4. 只动标记注释：可以插入新标记、改已有标记的文字、在标记前后断行；其它字符一个都不改。块尾和 `<script>`、`</body>` 挤在一行时不用断。
5. 稿子里没画的状态（只有一句文字说明也算没画）不硬插，记下来在摘要里报告。
6. 校验：`python3 SKILL_DIR/scripts/design_html.py verify <htmlFile>.pre-anchor <htmlFile>`。输出「一致」才删除副本；不一致时用副本恢复，重做这份。

稿子多时可以分批，或按份并行交给子 agent，每份独立处理；完成稿和设计稿可能同 id，分派时连同类型一起写明。

### 3. 检查

```bash
python3 SKILL_DIR/scripts/design_html.py check .hskill/sync-design/manifest.json
```

回到第 2 步处理仍列出的稿子，直到只剩第 2 步第 5 条记下的状态。

### 4. 写回与摘要

1. `manifest.json` 的 `version` 更新为 `5` 写回。
2. 输出摘要：迁移前后总大小；删除了哪些字体（预览时会回退到系统字体）；未解决的状态（稿子 id + 状态名）。
3. 询问是否 `git add`，建议 commit message：`chore: migrate HTML design drafts to partial-read format`

## 完成标准

- `check` 只列出摘要里报告过的未画状态，或输出「全部合规」。
- `manifest.json` 的 `version` 为 `5`。
