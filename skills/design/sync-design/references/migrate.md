# 批量迁移旧稿

把 manifest 登记的所有完成稿与设计稿迁到 SKILL.md「稿子结构」的格式，之后改稿才能局部读取。由初始化清单第 5 项或迁移模式触发。迁移是一次性成本：需要补标记的稿子要全量读一遍。

### 1. 脚本迁移

```bash
python3 SKILL_DIR/scripts/design_html.py migrate .hskill/sync-design/manifest.json
```

脚本原地改写每份稿子，只做机械变换，不改画面：

- 删除 base64 内嵌字体（字体名保留，回退到系统字体）
- 重复图标收进图标定义区，原处改为引用；样式里有选择器指向图标内部的跳过
- 状态名恰好是某个元素的 `id` / `data-ui-state` / `data-state` 且全文唯一时，在该元素前补状态标记

输出每份稿子的前后大小、做了什么，以及 `! 待补` 的状态。小于 40KB 的稿子不要求标记（直接全量读），不会出现在待补里。

### 2. 补状态标记

对每份有 `! 待补` 的稿子：

1. 全量读该稿。
2. 为每个待补状态找到画它的画面块，在块前插入一行标记，格式见 SKILL.md「稿子结构」。常见线索：状态名出现在标题、说明文字、`class` 或 `§` 编号里。
3. 没有独立画面块的状态（组合状态、靠切换实现的状态），在承载它的块的标记里写 `覆盖：状态1 | 状态2`；该块还没有标记就新加一个。
4. 只插注释，不改其它内容。标记独占一行：整个正文压在一行里的稿子，在插入点前后断行。
5. 稿子里确实没画的状态不硬插，记下来在摘要里报告。

稿子多时可以分批，或按份并行交给子 agent，每份独立处理。

### 3. 检查

```bash
python3 SKILL_DIR/scripts/design_html.py check .hskill/sync-design/manifest.json
```

回到第 2 步处理仍列出的稿子，直到只剩第 2 步第 5 条记下的状态。

### 4. 写回与摘要

1. `manifest.json` 的 `version` 更新为 `5` 写回。
2. 输出摘要：迁移前后总大小；删除了哪些字体（预览时会回退到系统字体）；未解决的状态（稿子 id + 状态名）。
3. 询问是否 `git add`，建议 commit message：`chore: migrate HTML design drafts to partial-read format`

## 完成标准

- `check` 只列出摘要里报告过的未画状态，或输出「全部合规」。
- `manifest.json` 的 `version` 为 `5`。
