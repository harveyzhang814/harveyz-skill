# git 工作流规划与执行分离 实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: 使用 superpowers:subagent-driven-development 逐项实施；用 `- [ ]` 跟踪步骤。

**Goal:** init-workflow 成为 git 策略的唯一解释者，部署时写出 `resolved.env`、工作流文档、hooks 与标准合并脚本；manage-worktree 与 compose-agentsmd 只读 `resolved.env`，manage-worktree 新增「合并」。

**Architecture:** init-workflow 的 `references/` 下新增 Python 解释器与部署入口，一次运行写出全部非 hook 产物；hooks 仍由 agent 按 `hook-templates.md` 生成，取值来自解释器。manage-worktree 的检测脚本改为两步读取基线分支上已提交的 `resolved.env`，新增 `merge-worktree.sh` 调用仓库内的标准合并脚本。compose-agentsmd 生成时从 `resolved.env` 取集成分支。

**Tech Stack:** Python 3 标准库（pytest 测试）；bash 3.2 兼容脚本（bats 测试）；Node.js（`node --test`）。

**Spec:** `.hskill/spec/2026-11-12-workflow-plan-exec-split/2026-11-12-workflow-plan-exec-split-spec.md`

**Spec Version and Scope:** v0.1，2026-11-12 批准；全文（第 2 节本轮做、第 7 节验收 1–10、第 9 节 S1–S14）。验收第 9 条与 agent-canvas 部署在合并后进行，见 Task 12。

## Global Constraints

- Python 只用标准库，不引入 PyYAML；shell 脚本兼容 macOS bash 3.2 与 BSD awk，只依赖 git 与 coreutils。
- 解释结果固定路径 `.hskill/init-workflow/resolved.env`；键集合与格式按 Spec 5.3；所有消费方逐行读取，不得 `source`。
- 自填区标记逐字为 `<!-- BEGIN PROJECT NOTES -->` 与 `<!-- END PROJECT NOTES -->`。
- 合并脚本路径 `scripts/merge-to-<merge_target>.sh`；提交标记行 `Merge-Via: merge-to-<merge_target>.sh`。
- 生成文件的首行标记：resolved.env 为 `# Generated by init-workflow <版本>`；合并脚本第 2 行为 `# Generated by init-workflow <版本>; edit merge.pre_checks in workflow-config.yml instead`。
- 版本：init-workflow `5.0.0`；manage-worktree `0.2.0`；compose-agentsmd `0.2.0`；compose-agentsmd 的 devflow 包 `VERSION` `2.0.0`（Spec 5.6 写“包 VERSION 升 0.2.0”会低于现值 1.0.0，删必填参数属不兼容变更，取 2.0.0）。每次改 SKILL.md 都同步 `skills-index.json` 的 `contentVersion` 与 `contentHash`（sha256 前 16 位，计算时把 `version:` 行替换为 `version: __HASH_PLACEHOLDER__`）。
- `manage-worktree` 新脚本退出码：0/1/2 透传合并脚本；3 非 git；4 未部署；5 工作区检测未通过；6 未配置合并目标；7 本工作区缺合并脚本。
- 合并前不写 agent-canvas，不写任何真实仓库的 staging；实走只在 `/tmp` 克隆副本中进行。不同步 `~/.claude/skills/` 装机副本（Spec R1）。
- 不改 archive-skill、contribute-skill、close-node（S11）。
- 提交信息 Conventional Commits，首行 ≤ 80 字符，结尾 `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`。

## Review Focus

- 主工作树停在另一分支且其工作树中的 `resolved.env` 取值不同 → 检测输出基线分支上已提交的取值（Task 6）。
- `merge.pre_checks` 某项失败 → 合并脚本退出 1，目标分支 ref 不变（Task 3）。
- 现有文档含自填区 → 重渲染后区内逐字节不变；不含标记且内容不同 → 覆盖并打印 `WARN` 与找回命令（Task 2）。
- 远端同步合并 `Merge branch '<目标>' of …` → commit-msg 与 pre-push 均放行（Task 4）。
- 配置没有 `base.feature` → 不写 `merge_target`/`merge_script`，文档保留通用合并写法，`merge-worktree.sh` 退出 6（Task 1、2、7）。
